# Glassbox 商品・集客・査読エンジン Working Ledger

Status: Working Note / Not Canon
Date: 2026-08-23
Source: 商品設計・市場調査・集客方式に関する対話

## 1. このメモの位置づけ

本メモは、2026-08-23時点で会話から形成されたGlassboxの「商品」「集客」「価格」「査読エンジン」の足場を一度固定するための作業台帳である。

正本ではない。市場調査、競合調査、実装検証、法規確認により変更する前提で保存する。

---

## 2. 製品境界

Glassboxの中心は、**銘柄を管理することではなく、銘柄を査読すること**。

扱うもの:
- 企業そのもの
- 財務・収益性・CF
- バリュエーション
- 株価の現在位置
- 市場で流通している期待や強気材料
- 支持材料 / 反証材料 / 未確認点
- 決算・ニュース・市況変化によって何が変わったか

扱わないもの:
- 推奨銘柄一覧
- Buy / Sell / Strong Buy等の売買方向の提示
- ポートフォリオ管理
- 保有比率管理
- 個人の資産額・取得価格・リスク許容度に応じた助言
- 発注・仲介

基本線:

> **人気だから扱う。人気だから買いとは言わない。**

> **選定は市場人気で決める。見解はGlassboxで決める。売買方向は決めない。**

## 3. 想定ユーザーフロー

当初の「購入30秒前」という理解は誤り。

**30秒チェック**は「注文直前の30秒」ではなく、**短時間で主要論点を確認できる**ことを意味する。

想定行動:

1. 銘柄探索 / 推奨銘柄との遭遇
2. 購入前の銘柄確認
3. 気になった銘柄の査読・深掘り
4. 購入
5. 決算・市況ニュース・価格変動等を契機に再確認

購入後も「含み益だから本物 / 含み損だから偽物」とは扱わない。

Glassboxが見るのは、企業・価格・期待・反証材料・不明点がその時点でどうなっているかである。

ライト層は明示的な投資仮説を立てない可能性が高い。製品側でユーザーに高度な仮説記述を要求せず、

> 「この銘柄どうなんだろう」

という曖昧な問いを、検証可能な論点へ内部変換する。

## 4. 集客構造

### 4.1 YouTube / インフルエンサー

役割: **需要形成・候補形成に近い導線**。

初手は自社動画。売買上位銘柄等、既に市場で注意を集めている銘柄を扱う。

想定導線:

> 売買上位3銘柄
> → Glassboxの査読結果を動画化
> → 概要欄
> → 「その銘柄、本物ですか？」
> → ソフト利用

将来、自社導線で転換率が確認できれば、インフルエンサー等へ集客・販売の一部を外注する余地がある。

コメント欄は個別相談窓口にしない。必要なら厳格管理し、製品導線と切り離す。

### 4.2 検索エンジン

役割: **既に生じた銘柄確認需要の捕捉**。

例:
- 銘柄名 + 今買い
- 銘柄名 + 割高
- 銘柄名 + 決算
- 銘柄名 + 下落理由
- 銘柄名 + 悪材料
- 銘柄名 + 将来性

Google Adsは金融系CPCが高くなりやすく、低単価買い切りソフトではCAC悪化リスクが大きい。

したがって初期は、

> **自社YouTube / SEO記事を主軸**
> → Google Adsは検索需要・CV仮説を小額で試す実験器具

とする方向が有力。

### 4.3 AI検索 / AI回答の出典

AI検索のソースクリック層は、既に一次資料・出典確認まで行う中上級者寄りで、Glassboxの初期ターゲットとしては弱い可能性がある。

一方、Glassboxの記事がAI回答の根拠として引用されることには、**分析IPの二次流通・ブランド形成**として価値があり得る。

AI検索は主販路ではなく、分析IP流通チャネルとして扱う候補。

## 5. メディア量産方式

外形は定石的な需要追随型コンテンツマーケティングを使う。

ただし中身は提灯記事ではなく、**査読型**とする。

基本ループ:

1. 売買上位銘柄等から3銘柄を機械的に選定
2. 財務・IR・ニュース・価格文脈を収集
3. Glassboxの査読正本を生成
4. 人間が数字・論点・見解を確認
5. 同じ正本から以下を生成
   - ソフト内30秒確認
   - 詳細査読レポート
   - YouTube台本 / 動画
   - SEO / AI検索向け記事
6. 流入・利用・購入を計測
7. 翌週へ反映

原則:

> **媒体を増やすのではなく、正本から媒体を生成する。**

動画はAI大量生成そのものを目的にしない。

> **査読を量産し、その成果を動画化する。**

動画編集は初期はVrew等の低コストツールで十分な可能性が高い。

## 6. 価格と体験版の暫定案

### 正価候補

> **4,980円 / 買い切り**

暫定根拠:
- 安すぎると「適当なAI株診断」に見えるリスク
- 1,000〜2,000円台では粗利が薄く広告耐性がない
- 1万円前後では無名初期製品として心理障壁が大きい
- 4,980円は「ちゃんとした査読ソフト」としての価格シグナルを出しやすい

価格は未検証。市場テストで要再評価。

### 体験版候補

日数制限・機能制限より、

> **任意の1銘柄を製品版と同品質で1回だけフル査読**

が有力。

理由:
- 機能制限すると価格納得感の中心である査読レポートの価値が伝わらない
- 日数制限は株を調べたいタイミングと一致しない
- 3銘柄以上無料だとライト層は無料だけで満足する可能性

想定ファネル:

> YouTube / 記事
> → 任意の1銘柄を無料査読
> → レポート完読
> → 4,980円買い切り

## 7. 価格納得感の三層

現時点では以下の三層が有力。

### 第1層: レポート項目

ユーザーが「4,980円で何が出るか」を最初に認識する層。

既存製品から学ぶ基礎項目と、Glassbox独自項目をハイブリッドする。

四季報的基礎情報は押さえるが、情報量競争には行かない。

### 第2層: 査読アルゴリズム

商品の中核。

数字を並べるだけでなく、

> **どの数字を、どういう条件で、どう判定するか**

を決定論的に実装する。

AI幻覚を避け、同じデータ + 同じEngineなら同じ結果になる再現性を重視する。

### 第3層: AI引き継ぎプロンプト

Glassboxで判定できない部分や、さらに深掘りしたい利用者向け。

Glassboxの査読結果・未確認点・反証候補を構造化した状態でChatGPT / Claude / Gemini等へ引き継ぐ。

Glassbox自身が巨大な汎用調査AIになる必要はない。

### 横串: Provenance

全層に、
- 出典
- 日付
- 対象期間
- 実績 / 予想
- 計算根拠
- Engine version

を付ける。

## 8. レポート構造の暫定案

### 8.1 企業カルテ / 基礎層

他製品から学び、必要十分な企業基礎情報を収録する。

候補:
- 企業概要 / 事業構成
- 売上 / 営業利益 / 純利益 / EPS
- 利益率
- 営業CF / FCF
- 自己資本 / 有利子負債
- ROE / ROIC等
- PER / PBR / 配当利回り
- 会社予想 / 市場予想
- 過去数年推移
- 株価レンジ
- 株主還元
- 業界 / 主要競合

四季報の再発明はしない。査読に必要な範囲に限定する。

### 8.2 Fundamental Review

査読本体。

候補:
- 成長は売上増か利益率改善か
- 純利益と営業利益の乖離
- 利益とCFの一致度
- 一過性要因の影響
- 会社予想の強弱
- 財務健全性
- 高配当の持続性
- 利益の質
- バリュエーションと企業品質の混同有無
- 重大な反証あり / なし / 判断材料不足

### 8.3 Valuation Review

「良い会社」と「良い価格」を分ける。

候補:
- 過去レンジ比較
- 同業比較
- 収益成長と評価倍率の整合
- 現在価格に織り込まれている期待の強さ

### 8.4 Price Context / 下落査読

チャートは価格予想ではなく、現在位置を理解するための文脈として使う。

候補:
- 52週高値 / 安値との距離
- 直近高値からのドローダウン
- 20 / 60 / 200日移動平均との位置
- 出来高変化
- ボラティリティ
- 下落速度
- 市場 / 業種指数との相対騰落

問い:

> **安くなったのか、悪くなったのか。**

「押し目買い判定」とはしない。

### 8.5 Event & Market Context

候補:
- 次回決算までの日数
- 直近決算からの日数
- 配当・権利日
- 株主総会
- 会社予想修正
- 重要製品発表等の企業イベント
- TOPIX / 日経等との相対推移
- 金利
- 為替
- 原油 / 商品価格等、業種・企業に関連する外部指標

市況は売買方向を出すためではなく、企業固有要因と市場要因を分離するために使う。

### 8.6 Counterevidence / Unknowns

- 強気材料を弱める事実
- 重大な反証が確認できない場合はその旨を明記
- 無理にベアケースを捏造しない
- 判断材料不足を正常状態として扱う

### 8.7 AIでさらに査読する

詳細調査が必要な場合に外部AIへ渡す。

## 9. 査読エンジンの設計方針

### 9.1 決定論的アルゴリズムを優先

AIなしで処理できるものは可能な限りアルゴリズム化する。

例:
- 財務推移
- 利益率
- CF乖離
- バリュエーション
- 株価位置
- 市場 / 業種比較
- 会社予想修正
- カレンダーイベント

利点:
- AI幻覚を避けられる
- 再現可能
- 監査可能
- 低ランニングコスト
- 同時点・同Engineなら全ユーザーへ同じ結果

### 9.2 AIの役割を限定

AIが必要になりやすい部分:
- 市場で流通している主要な物語 / 期待の抽出
- IR・ニュースの意味理解
- 事実と論点の対応付け
- 定型ルールで扱えない未知論点の抽出

AIには数値そのものを決めさせず、意味理解・編集者的役割へ寄せる。

将来的にはバッチ処理でAI結果を検証済みJSONへ保存し、ユーザー利用時は再推論せず表示する方式も候補。

## 10. Engine versioning 仮説

アルゴリズム型であるため、方法論を版管理できる。

候補:

- Glassbox Engine 2026
- Glassbox Engine 2027

区別:

> **データは更新する。方法論は版管理する。**

旧版でもデータ更新・不具合修正は行う一方、新しい査読ルール・業種別ロジック・評価方法等は新Engineへ載せる。

結果画面には例えば、

- Data as of
- Engine version
- Rule Set

を表示する。

買い切りモデルでは、新Engineを任意の有償アップグレードとして提供する余地がある。

この方式は未決定。旧版サポートコストを含めて要検証。

## 11. 既存手法の利用方針

Glassbox独自の投資理論を発明することは目的ではない。

古典から現代まで公開されている成熟した銘柄分析手法を調査し、査読目的に再構成する。

調査候補例:
- DuPont分析
- Piotroski F-score
- 利益の質
- CF分析
- 財務レバレッジ
- バリュエーション比較
- 成長率分解
- テクニカル指標の価格文脈利用
- イベント / カレンダー分析
- 市況・業種相対分析

一つの流派を正解として採用せず、各手法の用途・前提・弱点も確認する。

## 12. 次に調べるもの

### A. 既存製品の項目棚卸し

候補:
- 四季報
- Simply Wall St
- Morningstar
- TradingView
- その他主要な個人投資家向け分析サービス

目的:

> **既存商品の良い項目を真似る部分と、Glassbox独自項目を分離する。**

### B. 銘柄分析手法の棚卸し

古典〜現代の公開分析手法を、
- 何を見るか
- 何を検出できるか
- どんな誤判定があるか
- データ取得可能性
- アルゴリズム化可能性

で整理する。

### C. `レポート項目表 v0.1` を作る

A/Bを踏まえ、

> **4,980円で何を出すか**

を項目レベルで確定する。

その後に査読アルゴリズムの仕様へ落とす。

GUIの本格作り込みはその後。

## 14. 現時点の短い要約

Glassboxは、金融総合ソフトにも予想屋にも行かない。

> **銘柄を入れると、その銘柄を検証可能な形で査読するソフト。**

商品価値は、

1. 価格納得感を作る査読レポート
2. AI幻覚を避ける再現可能な査読アルゴリズム
3. 必要時のみ深掘りへ渡すAI引き継ぎ

の三層で作る。

集客は、売買上位等の既存注意をYouTube・記事で拾い、製品へ接続する。

次工程は、**既存製品の項目棚卸し + 公開済み銘柄分析手法の棚卸し → レポート項目表 v0.1**。
