# Original Question Principle

Status: Canon

## 中核原則

> **決定木は捨ててもよい。原問いは捨てない。**

Glassbox Investing は、ユーザーが最初に持ち込んだ問いを、ソフトウェア側の分類・決定木・入力様式に合わせるために上書きしない。

ユーザーの問いが曖昧、雑、感情的、未整理であっても、それ自体を出発点として保存する。構造化は原問いを置換するためではなく、原問いを理解・検証・精密化するための補助表現として扱う。

典型的な入口である「どれ買えば儲かる？」のような問いも、そのまま原問いとして保持し、その後の分類や分解によって消去しない。

## 原問いと構造化表現を分離する

Glassbox Investing は、少なくとも以下を分離して扱う。

1. **原問い（Original Question）**
   - ユーザー自身の言葉で入力された問い
   - 後続の分類によって書き換えない
   - 後から当時の問題意識を再現できる形で保持する

2. **解釈・分類（Interpretation / Classification）**
   - テーマ探索、銘柄比較、割安性確認、保有銘柄評価等のソフトウェア側の補助分類
   - 原問いそのものではない
   - 必要なら複数候補を併存させる

3. **精密化された問い（Refined Question）**
   - 検討の進行によって生まれた、より検証可能な問い
   - 原問いを消さず、追加・版管理する

例：

```text
原問い v1
「ポーランド復興でまだ上がっていない株ない？」

解釈候補
- テーマ株探索
- 出遅れ株探索
- 割安性確認

精密化 v2
「公益企業そのものではなく、復興・設備投資の供給側で、業績成長が株価へ十分織り込まれていない上場企業を探す」
```

## 決定木は補助線であり、強制経路ではない

決定木、ウィザード、質問フローは、ユーザーの思考を整理するための道具として用いる。ただし、決定木を完走すること自体を製品目的にしない。

選択肢にユーザーの意図が存在しない場合、ユーザーに不適切な分類を強制してはならない。

各主要分岐では、必要に応じて以下の逃げ道を持たせる。

- どれも違う
- このまま進める
- 補足を追加する
- 既に確認済み
- 関係ない
- 分からない
- この工程を飛ばす

「その他」を選択した結果、別の固定的な決定木へ戻され続ける設計は避ける。

## 「確認済み」を正式な状態とする

Glassbox Investing は、ユーザーが既に行った調査を繰り返させない。

各検討項目は、単なる未入力／入力済みではなく、必要に応じて次のような状態を持てるようにする。

- 未確認
- 確認したい
- 確認済み
- 関係ない
- 分からない

これにより、PER、決算、競合比較、受注残等を既に確認したユーザーに対し、同じ初歩的確認を何度も要求することを避ける。

既知事項を再実行させるのではなく、**現在まだ残っている論点は何か**を示すことを優先する。

## 現在地と質問理由を可視化する

Glassbox Investing が追加質問を行う場合、その質問が原問いとどう接続しているかを可能な範囲で示す。

例：

```text
原問い
「この株は高値掴みか？」

確認済み
✓ PER
✓ 同業比較

現在地
→ 市場が高い倍率を許容している理由の確認

次に聞く理由
利益成長が高倍率を正当化している可能性と、単なる期待先行を分けるため
```

ユーザーが「なぜこれを聞かれているのか」を理解できない質問を連続させない。

## 原問いの精密化履歴を残す

投資研究では、調査の途中で問いそのものが変わることがある。それを失敗や脱線として扱わず、認知の更新として保存する。

```text
Original Question v1
    ↓
補足・反証・新事実
    ↓
Refined Question v2
    ↓
さらに調査
    ↓
Refined Question v3
```

後から、最初に何を知りたかったのか、何を見て問いが変わったのかを追跡できることを重視する。

## サポートボット型の徒労を避ける

Glassbox Investing は、固定された質問順を消化させることによってユーザーへ徒労感を与える設計を避ける。

特に次をアンチパターンとする。

- 選択肢に意図がないのに最も近いものを選ばせる
- 既に実施済みの確認を繰り返させる
- 「その他」を選んでも固定経路へ戻す
- システム上の分類が原問いより優先される
- 回答を重ねても原問いへの距離が縮まっているか分からない
- 決定木の完走が目的化する

## 設計上の優先順位

対話型UI、決定木、スコアリング、将来のAI機能はすべて交換可能な実装手段である。

一方、原問いはユーザー側の目的そのものであり、実装都合によって失ってはならない。

したがって、設計上の優先順位は以下とする。

> **ユーザーの原問い ＞ 精密化された問い ＞ 分類・決定木 ＞ UI上の都合**

Glassbox Investing の役割は、ユーザーを決定木へ従わせることではない。原問いを保持したまま、そこから検証可能な問いへ移動するための足場を提供することである。
